快速开始

请在后台“商户管理 → 更多 → 对接信息”复制接口地址和商户编码。API Key 只在创建或重置时显示一次，请保存在服务端环境变量中。
  1. 准备商户编码和 API Key。
  2. 使用服务端调用创建订单接口，保存返回的平台订单号和支付二维码。
  3. 用户支付后，以回调通知为准；回调异常时可主动查单。

认证方式

所有开放接口请求都应携带以下请求头：

x-merchant-code: YOUR_MERCHANT_CODE
x-merchant-key: YOUR_API_KEY
content-type: application/json

如果后台启用了签名校验，还需按接口文档补充 x-merchant-timestamp、x-merchant-nonce 和 x-merchant-signature。API Key 请勿放在浏览器、前端脚本或公开仓库中。

创建订单

POST/api/v1/orders
请求示例
{
  "amount": 100,
  "description": "测试订单",
  "clientRequestNo": "ORDER_202611070001",
  "paymentMethod": "NATIVE",
  "collectionMode": "NATIVE"
}

金额单位为分。collectionMode=NATIVE 只走微信 Native 统一下单并生成动态 codeUrl；collectionMode=QR 只走已导入的挂码，不能与公众号支付组合。公众号支付传入 paymentMethod=JSAPI，首次请求会返回微信授权地址，授权回跳后携带一次性 oauthToken 重试原请求。

订单查询

GET/api/v1/orders/{platformOrderNo}
返回字段重点：status、amount、transactionId、paidAt
/api/v1/orders/{platformOrderNo}

回调通知

平台会向订单创建时的通知地址发送支付结果。业务方必须先校验签名，再按订单号幂等处理；收到通知后返回 HTTP 200，重复通知不得重复入账。

{
  "event": "PAYMENT_SUCCESS",
  "platformOrderNo": "P...",
  "amount": 100,
  "status": "SUCCESS",
  "transactionId": "wx..."
}

错误与状态

  • SUCCESS：支付成功。
  • QR_CREATED / PAYING：等待支付。
  • UNKNOWN：状态待查，建议稍后重试查询。
  • FAILED / CLOSED：订单失败或已关闭。
  • 401：认证信息错误；403：商户或通道无权限；429：触发风控或频率限制。
